# QR Menu Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle every route of QR Menu into one ink + cream editorial design system without changing behaviour.

**Architecture:** The app already routes almost all styling through one class system: `app-*` and `food-*` classes in `app/styles/app.css` and `auth-*` classes in `app/styles/auth.css`, driven by `--app-*` CSS variables. Pages also use those variables in Tailwind arbitrary values such as `bg-[var(--app-bg)]`. So we retoken that system in place (one source of truth), expose the same tokens to Tailwind through `@theme`, then rebuild the page layouts that need structural change (landing, auth, the owner app shell, diner views). This replaces the spec's "delete app.css, convert to Tailwind classes" approach: same result, far less churn. The spec has been updated to match.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind v4, framer-motion, lucide-react, next/font (Fraunces and Inter are already loaded as `--font-fraunces` and `--font-inter`).

**Spec:** `docs/superpowers/specs/2026-09-30-redesign-design.md`

## Global Constraints

- Tokens: ink `#0B0B0C`, paper `#F6F1E7`, card `#FFFDF8`, line `rgb(11 11 12 / 0.12)`, muted `#6B645A`, accent `#D7261E`, success `#1F7A4D`.
- The accent is never used for body text; it's for highlights, the focus ring and status dots only.
- Display type: Fraunces with `font-variation-settings: 'opsz' 144`. UI and body type: Inter.
- Radii: cards 14px, buttons and chips fully rounded (pill).
- Motion never hides content: elements start visible, and `prefers-reduced-motion` disables animation.
- No behaviour, data, route or copy-claim changes. No new runtime dependencies. Remove `three`, `@react-three/fiber`, `@react-three/drei` and `@types/three`.
- Every form control has a linked label (`htmlFor`/`id`).
- Layouts work at 360px wide with no horizontal scroll.

## Review Focus

1. Long restaurant or food court names (40+ characters) must wrap or truncate cleanly in the app header, stall cards and the diner name pill. Pinned in Task 5 (a screenshot with a long-name fixture).
2. A restaurant with no menu PDF must show a styled empty state on `/menu/[slug]`, not a blank iframe. Pinned in Task 5.
3. Keyboard-only users must see a visible focus ring on every button, link and input (the red accent ring). Pinned in Task 1 (tab through `/login`).
4. Mobile width (390px) must have no horizontal scroll on any route. Pinned in Task 7 (a screenshot sweep that checks `scrollWidth` is not greater than `clientWidth`).
5. The existing flows must still work: signup, onboarding upload, adding a stall, role guards. Pinned in Tasks 3–7 by re-running the 31-check e2e suite.

## Test harness (used by every task)

- e2e: `scratchpad/e2e/suite.py`, run against `npm run start -- -p 3100`. It signs up two owners through the form and exercises everything; the test users and files are deleted afterwards with the cleanup commands from the session.
- Screens: `scratchpad/shots.py` takes each route at 1440×900 and 390×844 (logged-out routes, plus owner routes via a signed-up test owner). It fails if `document.documentElement.scrollWidth > clientWidth` at 390.
- Gates: `npx eslint` (0 errors), `npx tsc --noEmit`, `npm run build`.
